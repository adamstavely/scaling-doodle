Intellect

Research portfolio management,
documented for build.

Intellect is a portfolio-intelligence console for a research lab director and their principal investigators — it tracks topics, open questions, knowledge gaps, work in flight, papers, impact, people and money across the whole organization, with a full traceability spine from question to citation. This document is the complete specification a developer needs to rebuild it.

01

What this is & how to read it

Two audiences use Intellect: a Lab Director (Chief view) who needs whole-portfolio health, resourcing and risk; and a Principal Investigator (PI view) who needs their own topics, gaps and impact. The same screens re-scope to the active role.

Read the design files as references, not source
The bundled files are a working HTML/React prototype that demonstrates the intended look, layout and behavior. They are not production code to lift directly. The task is to recreate these designs inside the target codebase using its own framework, component library and conventions — or, if starting fresh, to pick an appropriate stack (React, Vue, Svelte, SwiftUI…) and implement them there. Treat every measurement, color and interaction below as the contract; treat the prototype's file structure as illustrative.

The mental model

Everything hangs off a single linked data graph. A Topic owns Questions; questions surface Gaps; gaps are addressed by Work (projects); work produces Papers; papers earn citations. The Topic Detail screen renders this chain literally as a left-to-right "traceability spine." Most other screens are roll-ups and rankings over the same graph.

Accent is user-swappable
A Tweak lets the user repoint the primary accent (--gold/-2/-dim, used by P1 badges & active nav) to one of three navies/teals: #1D3557, #0073E6, #0E7C86. Each has light + dark variants (SIGNAL map). Build the accent as a themeable token, not a hardcoded color.

App shell & layout

A fixed left sidebar, a sticky topbar, and a scrolling content column. Every screen's inner content is centered at max-width:1440px with 22–26px horizontal padding.

Sidebar
212px fixed. Logo, 7 nav items, flexible spacer, "Portfolio review" promo card with a Prep brief button. Active item: linear-gradient(90deg,--gold-dim,transparent) + a 2.5px accent rail + accent-colored icon. Background --bg-2, right hairline border.
Topbar
60px sticky, backdrop-filter:blur(8px), translucent. Holds a centered 440px search field (placeholder + ⌘K hint), the role switch, a notification bell with unread dot, and the current user's avatar + name + role.
Nav items
Dashboard · Organization · Research Topics · Gaps & Coverage · Resourcing · Papers & Impact · People. Each a stroke icon (1.6 weight, 24px grid) + label.
Content grids
Dashboard 2.05fr / 1fr; Papers 320px / 1fr; most detail screens use 1fr / 1fr or a stat-cluster header. Card gap 14px.
Atoms (.css)
.panel white card, 1px --line, radius 12px, --sh-1. .btn / .btn-gold (filled accent) / .btn-ghost. .chip mono pill. .dot health dot with colored halo.

08

Roles, scope & navigation

Role switch
Pill toggle in the topbar: PI view (Marcus Okonkwo) ↔ Chief view (Helena Vance). Default = Chief. Switching recomputes scope.
Scope object
{ isChief, topics, person }. Chief → all topics + lab aggregates. PI → only topics they lead or on their team. Every screen takes scope and renders accordingly; chief sees institute-wide roll-ups, PI sees per-topic sums.
Routing
Single route = {view, params} in App. go(view, params) sets it and scrolls content to top. No URL routing in the mock — add real routes (/topic/:id, /papers/:id) in production.
Deep-link params
topic→topicId, papers→paperId. Cross-screen links (gap→topic, impact→paper) pass these.
09

Paper grades

A qualitative assessment attached to each paper, surfaced in three places. A four-level scale, color-coded on the semantic ramp.

Outstanding Excellent Satisfactory Dissatisfactory
Data
A grade string on each paper: "outstanding" | "excellent" | "satisfactory" | "dissatisfactory". The GRADE map holds label + color + tint per level.
Paper detail
A labeled "Assessment" badge top-right of the paper header — colored dot + level name on a tinted pill.
Paper list
A small color dot beside each title for scannability.
Topic roll-up
In the Topic Detail resourcing strip: a stacked color bar + per-grade counts ("N assessed"). Zero-count grades show dimmed for a stable legend.
Build note
Grade is the contract: a fixed 4-level enum, never free text. In production it should be an editable field (a reviewer assigns it), with the roll-up recomputing live. Keep the color mapping centralized so badge, dot, list and roll-up stay in lockstep.

13

Implementation notes

  • Tokens first. Port styles.css custom properties into your theming system before building any screen. Both Light and Dark must come off the same names; the accent must be swappable.
  • Numbers are mono & tabular. Every metric, delta, date and chip uses JetBrains Mono with font-variant-numeric:tabular-nums. This is load-bearing for table alignment — don't substitute the UI font.
  • Color = meaning. Green/amber/rose/blue are reserved for status. Never use them decoratively; never invent new hues for new states — extend the semantic set deliberately.
  • Charts are hand-rolled SVG (Sparkline, Ring, StackBar, MiniBars) — lightweight and themeable. You may swap in a chart lib, but match stroke weights, easing and the no-axis, label-light aesthetic.
  • Scope everything by role. Every list, sum and roll-up must respect the active Chief/PI scope. Build it as a single source of filtering, not per-screen conditionals.
  • Density is intentional. 13–14px body, tight 14px gaps, hairline dividers. Resist inflating spacing — the product reads as an instrument panel, not a marketing site.
  • Accessibility. Keep the :focus-visible ring, honor prefers-reduced-motion, and don't rely on the health/grade dot color alone — always pair it with a text label (as the chips do).
